<objective>
Add a new facet `GNUSRedeemAdapter.sol` to the GeniusDiamond that provides a generic, permissionless `redeem(address from, uint256 childId, uint256 amount, address recipient)` entry point. This adapter enables any conforming external ERC-20 proxy contract to convert a user's proxied-child ERC-1155 holdings into GNUS in a single transaction, without taking custody across transactions and without modifying the shipped `GNUSTreasury.convert` function.

Purpose: Implements PROXY-03 (criterion 5 of Phase 11) under the conversion-native model (Phase 9 D1/D2). Resolves D-08 via its option (a): because `_msgSender()` inside a diamond delegatecall is the caller (the proxy), not the user, the adapter pulls the child ERC-1155 from `from` into the diamond via `_safeTransferFrom` (user pre-approves the diamond once), then inlines `_burn`/`_mint` rather than calling `this.convert()` — preserving per-caller limiter attribution keyed to `from`. The proxy-side PROXY-01/02 work lives in the erc20-gnus-proxy workstream; this plan covers ONLY the diamond-side adapter.

Output: New file `contracts/gnus-ai/GNUSRedeemAdapter.sol`, modified `diamonds/GeniusDiamond/geniusdiamond.config.json`. Tests live in Plan 11-02; this plan ships production code only.
</objective>
