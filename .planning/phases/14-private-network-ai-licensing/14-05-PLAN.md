<objective>
Close the network-key mint-validation gap discovered in the 2026-08-25 /gsd-explore session
(`.planning/todos/pending/phase-14-1-network-key-mint-validation.md`) so `privateNetworkId` can
safely serve as the network's Ed25519 public key (raw uint256).

Design decisions locked for this plan (from the gap scope + D-01..D-29; do not re-litigate):

1. **Zero/duplicate rejection at license creation.** `privateNetworkId == 0` reverts (a real
   Ed25519 pubkey is never zero; zero = public, and a license IS a private-network identity).
   Duplicates revert via an appended `networkIdToLicense` mapping in GNUSLicensingStorage —
   storage append in the LICENSING layout only; the NFT struct (slots +11..+13) is FROZEN.

2. **Credit binding via lazy propagation at purchase time.** In `purchaseCredits`: if the
   credit token's `privateNetworkId` is 0, write the parent license's value (provenance is
   CREATOR-gated at license creation, so a permissionless caller — D-27 — only triggers a
   write of already-trusted data; no operator-gated setter surface added). If it is nonzero
   and differs from the license's, revert. Public credits (child index 1) stay 0.

3. **Fixed-in-SKU split allocation (research question #5 resolved).** The operator fixes the
   per-leg amounts in the SKU; the buyer picks among SKUs, never supplies amounts
   (preserves D-27 permissionlessness — no new purchase-path parameter surface — and D-10
   exact-burn accounting: `totalSupply` delta == priceInMinions regardless of leg split).
   Buyer-chosen splits at purchase are DEFERRED (note in code comment + research log close-out).

4. **SKU append shape:** append ONE field `uint256 publicCreditAmount` to `SKU` after `active`.
   Existing `creditAmount` semantics become the PRIVATE leg. Zero-default (0) = private-only —
   every existing SKU decodes unchanged (append-only, backwards compatible).

5. **Public-leg mint target:** the license's SECOND child, `(licenseId << 128) | 1`
   (`_PUBLIC_CHILD_INDEX = 1`), created by the operator through the EXISTING generic
   `createNFTWithLifecycle` surface (parent-creator auth, D-02 hierarchy: still a company
   child of the license). No lazy creation code in the purchase facet — the purchase path
   requires `nftCreated` (same `_ERR_CREDIT_TOKEN_MISSING`-style gate) exactly like the
   private leg. Minimal change; consistent with D-02.

Purpose: mint-time integrity of the network-key identity before shipping Phase 14.
Output: validated license/credit network binding + split-mint SKU rail, proven by ~8 new tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| buyer → purchaseCredits | Permissionless (D-27): caller supplies only skuId/licenseId/deviceWallet — no amounts; all economic values come from the operator-gated SKU record |
| operator (CREATOR/ADMIN) → createLicense / configureSKU | Role-gated writes of network identity and SKU leg amounts |
| purchase path → NFT storage | Permissionless caller triggers a lazy privateNetworkId propagation write — value is copied from CREATOR-gated license storage, never caller-supplied |

## STRIDE Threat Register (ASVS L2)

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-05-01 | Spoofing | createLicense network identity | mitigate | reject privateNetworkId == 0 + networkIdToLicense uniqueness mapping (a second license can never claim an existing Ed25519 key) |
| T-14-05-02 | Tampering | purchaseCredits lazy propagation | mitigate | propagated value read ONLY from the license NFT record (CREATOR-gated at creation); buyer input never reaches the write |
| T-14-05-03 | Tampering | public-leg token network binding | mitigate | require public token privateNetworkId == 0 at purchase — a poisoned public token cannot ride the split rail |
| T-14-05-04 | Repudiation | split-mint audit | mitigate | both legs mint through the shared hook (Transfer events) and the single burn emits ERC-20 Transfer(to=0) — totalSupply delta == price remains provable |
| T-14-05-05 | Denial of Service | EIP-170 facet overflow | mitigate | bytecode size asserted <= 24,576 in <automated>; helper-split fallback documented in Task 3 |
| T-14-05-06 | Elevation | SKU leg amounts | mitigate | amounts fixed in the CREATOR/ADMIN-gated SKU (fixed-in-SKU resolution) — no purchase-path parameter surface for buyers |
| T-14-05-SC | Tampering | package installs | accept | no new dependencies — pure Solidity edits to existing files |
</threat_model>
